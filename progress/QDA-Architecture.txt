# Quick Deploy Agents

# Technical Design Document (v1.0)

## Purpose

This document describes the technical architecture of Quick Deploy Agents.

Unlike the PRD, which defines the product, this document defines how the system will be built.

---

# High-Level Architecture

```
                   Client
                      │
          REST API / Dashboard
                      │
──────────────────────────────────────
              Control Plane
──────────────────────────────────────

Authentication

↓

API Gateway

↓

Controllers

↓

Services

↓

Repositories

↓

PostgreSQL

↓

Redis

↓

BullMQ

↓

Deployment Scheduler

──────────────────────────────────────
             Execution Plane
──────────────────────────────────────

Deployment Worker

↓

Docker

↓

Running Agent

↓

LLM Provider APIs
```

The Control Plane manages users, authentication, deployments and metadata.

The Execution Plane runs isolated agent workloads.

# Design Principles

* API-first architecture
* Stateless backend
* Resource-oriented REST API
* Separation of concerns
* Provider agnostic
* Container isolation
* Secure by default
* Horizontal scalability
* Idempotent deployment requests

## Agent Service

Responsibilities

* Create agents
* Update configuration
* Version agents
* Validate configuration

Deployments always reference a specific version.

---

## Deployment Service

Responsibilities

* Validate deployment requests
* Create deployment records
* Queue deployments
* Track deployment lifecycle
* Stop deployments
* Restart deployments

Deployment States

Pending

Queued

Building

Starting

Running

Stopping

Stopped

Failed

Completed

---

## Execution Worker

Responsibilities

* Consume deployment jobs
* Pull agent configuration
* Provision isolated runtime
* Inject secrets
* Start agent
* Report status
* Stream logs
* Cleanup resources

Execution workers never expose public APIs.

# Error Handling

Controllers never expose raw exceptions.

Services throw domain errors.

Global error middleware converts domain errors into HTTP responses.

Example

```
AgentNotFoundError

↓

404 Not Found
```

```
InvalidProviderKeyError

↓

401 Unauthorized
```

```
DeploymentFailedError

↓

500 Internal Server Error
```

# Guiding Principle

Quick Deploy Agents is divided into two independent systems.

**Control Plane**

Owns users, agents, authentication, deployments, metadata and scheduling.

**Execution Plane**

Owns container creation, agent execution, lifecycle management and runtime isolation.

The Control Plane decides **what** should run.

The Execution Plane decides **how** it runs.
